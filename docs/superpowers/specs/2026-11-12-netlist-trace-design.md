# netlist_search 设计文档

日期：2026-11-12
状态：待评审

## 1. 背景与目标

流片前的 netlist ECO 中，需要在一个约 620M / 一千万行的门级网表里，从"某一个模块中的某一根 wire"出发向前追溯它的所有 driver，一直追到寄存器、未知 cell（黑盒）和模块端口。追溯完成后，把路径上的中间 wire 的门级逻辑还原成人类可读的 RTL 风格表达式，用于定位状态机的条件分支、组合逻辑中的某一条逻辑。

参考 `grammar.example`，还原能力至少包括：

```
grammar                       logic
cnt[3:0] == 5                 cnt[0] & (!cnt[1]) & cnt[2] & (!cnt[3])
sel? a : b                    sel & a | !sel & b
```

即：不只是布尔化简，还要做**总线级、字级（word-level）的模式还原**。

工作语言：Rust（本机 1.89.0）。纯命令行工具，无 GUI。

## 2. 输入

| 输入 | 说明 |
|---|---|
| `--netlist <file>` | 门级结构化 Verilog 网表，可给多个文件（`.v` / `.vg`）。约 620M、一千万行 |
| `--lib <file>` | Liberty `.lib` 文本，可给多个。提供 pin 方向、`function`、`ff` / `latch` group |
| `--inst <hier_path>` | 目标所在的**例化名**（层次路径）。省略表示 wire 在顶层模块中 |
| `--wire <name[idx]>` | 目标 wire 名；带索引则只追该位，不带索引若是总线则逐位追溯 |
| `--top <module>` | 顶层模块名。省略时自动判定 |
| `--no-cross` | 关闭跨模块追溯 |
| `--max-hier-depth <N>` | 跨模块的层次深度上限，默认 8 |
| `--filter <pattern>` | 只显示依赖某信号的中间 wire（子串匹配端点显示名） |
| `--radix dec\|hex\|bin` | 常量进制，默认 `dec`（`cnt[3:0] == 5`）；`hex` / `bin` 输出带位宽的 `4'h5` / `4'b0101` |
| `--max-nodes <N>` | 锥的节点预算，默认 200000 |
| `--expand` | 端点式超出输出预算时仍然完整打印 |
| `--strict` | 禁止输出未经证明的表达式（见 §6.6） |
| `-o <file>` | 报告输出文件，默认 stdout |

### 2.1 例化名而不是模块名

`--inst` 是例化名（层次路径），因为只有例化名唯一确定一个实例。由此带来两个简化：

1. **父链已知**。跨模块向上追溯时，不需要反查"谁例化了这个模块"，路径本身给出了父链。多例化歧义因此消失。
2. 不需要 `--inst` 之外的定位参数；`--module + --inst` 的组合被取消。

路径解析规则：

- 分隔符 `/`（同时接受 `.`）。
- 首段可以是顶层模块名，也可以直接是顶层下的例化名。例：`top/u_core/u_fsm` 与 `u_core/u_fsm` 等价。
- 展平网表中例化名内含 `/`（如 `\u_core/u_fsm/U123 `），按"每层最长匹配"贪心切分。
- 未给 `--top` 时自动判定顶层：在模块索引中找出未被任何模块例化的模块。多个候选时，用路径逐一尝试解析；仍不唯一则报错并列出候选。
- 若给定路径无法从顶层完整解析，退化尝试"唯一后缀匹配"（例如只给 `u_fsm`）。唯一命中则使用；命中多个则报错并列出所有候选路径。
- 后缀匹配需要完整层次信息，此时并行解析全部模块（此路径较慢，报告会说明）。

### 2.2 顶层模块与实例路径的解析代价

- 正常路径（`--top` 已给，或首段是模块名）：只解析路径上经过的模块，**按需惰性解析**。
- 自动判定顶层：第一遍索引过程中记录"被例化的模块名集合"，不需要解析模块体（见 §4.1）。
- 唯一后缀匹配：并行解析全部模块（rayon），仅在用户给了不完整路径时发生。

## 3. 输出

单份文本报告，纯 ASCII 英文标签（便于 grep、回贴到 EDA 流程里）。

```
=== Cone of u_core/u_fsm/next_state[2]   (module fsm) ===

Endpoints (7):
  [REG]     state[3:0]             inst state_reg[3:0]            DFFRX2  Q
  [REG]     u_core/u_cfg/mode[1]   inst u_core/u_cfg/mode_reg[1]  DFFRX2  Q    (via input port mode[1])
  [UNKNOWN] u_core/u_sram/U0       cell SRAM_1024x32 not in lib; pin dout[7] drives n1071
  [CONST]   1'b0

Wires (depth 1..4):
  d1  n1023          U910  NOR4X1
        local:    !(state[3] | n88 | state[1] | n90)
        endpoint: state[3:0] == 5
  d1  n1044          U944  NOR4X1
        local:    !(n87 | state[2] | state[1] | n90)
        endpoint: state[3:0] == 9
  d2  n1102          U998  OR2X1
        local:    n1023 | n1044
        endpoint: state[3:0] inside {5, 9}
        aliases:  == n2211, == !n2212
  d3  n1130          U1130 AND2X1
        local:    mode[1] & n1102
        endpoint: u_core/u_cfg/mode[1] & (state[3:0] inside {5, 9})
  d4  next_state[2]  U1140 BUFX2
        local:    n1130
        endpoint: (same as n1130)

Notes:
  - u_core/u_sram/U0 (SRAM_1024x32) is a black box: function of dout[7] unknown, cone stops there.
  - Cone complete: 137 net bits visited, no truncation.
```

要点：

- 每个中间 wire 一段，含**驱动实例名 + cell 类型**（ECO 时直接可用）、局部式 `local`（用上一级 wire 表示）、端点式 `endpoint`（用寄存器/端口/常量表示）。
- 按距目标信号的深度排列。
- 端点式过大（见 §6.5 预算）时省略，只给出依赖端点数。
- 函数相同或互为取反的 wire 标注在 `aliases` 里。
- 未知 cell、假设、截断都进 `Notes` 单独说明。
- 命名规则：目标实例内部的名字不带前缀；其他实例里的名字用从顶层开始的完整路径。

## 4. 加载与索引

### 4.1 第一遍：索引（单次顺序扫描）

用 `memmap2` 映射文件，手写字节级词法分析，不整文件读入内存。产出：

- `module name -> (start_offset, end_offset)`：模块字节范围。
- `instantiated_type_names: HashSet<symbol>`：语句起始位置出现的非关键字标识符（即被例化的 cell / 模块类型名）。用于顶层自动判定，不需要解析模块体。
- 词法层面需正确跳过：`//` 与 `/* */` 注释、字符串、转义标识符 `\foo[3] `（以空白结束）、`$` 系统任务。

编码按字节处理，不做 UTF-8 校验（网表名基本是 ASCII；GBK 注释不会打断解析）。

### 4.2 第二遍：按需解析模块体

只解析锥经过的模块。数据模型全部用 `u32` 索引和 intern 后的符号，避免指针与重复字符串：

```
Module {
  name: Sym,
  ports: Vec<Port{ name: Sym, dir: Dir, msb: u32, lsb: u32 }>,
  nets:  Vec<Net{ name: Sym, msb: u32, lsb: u32 }>,   // 位化后的 net bit id
  instances: Vec<Instance{ cell: Sym, name: Sym, conns: Range<u32> }>,
  conns: Vec<Conn{ pin: Sym, net: NetBitRef }>,        // 支持 .pin(net) / 位置连接
}
```

- net bit 的引用形式为 `(net_id, bit_index)`；`net[3:0]` 与 `net[7:4]` 这种部分连接、拼接 `{a[1], b[0]}`、常量 `1'b0` 都展开成位。
- **pin 方向解析**：
  - cell 在 lib 中：用 lib 的 pin 方向。
  - cell 是网表里的模块：解析该子模块的**头部**（只扫 `input/output/inout` 声明，端口方向齐了就在遇到第一条例化语句时停止），拿到端口方向即可，不建完整结构。
  - cell 两边都不是：未知 cell，pin 方向未知（见 §5.2）。
- 惰性解析意味着模块被访问才占内存；单次查询通常只解析极小一部分文件。

### 4.3 内存与性能目标

| 指标 | 目标 |
|---|---|
| 620M 网表索引（第一遍） | < 10 s |
| 单次查询（含索引 + 按需解析 + 报告） | < 15 s |
| 峰值内存 | < 2 GB |

这些是目标值。我会生成同规模的合成网表实测，并把实测数字写进 README，不达标就继续优化（第一遍索引可并行化：按 `endmodule` 边界切块后多线程词法扫描）。

## 5. 追溯算法

### 5.1 表示

追溯在**实例上下文**中进行，节点是 `(ctx, net_bit)`，`ctx` 是一个实例路径。位级追溯，因为总线级还原（`==`、mux、索引）必须以每位函数为基础。

从目标 `(ctx0, wire)` 出发做反向 BFS/DFS，节点预算 `--max-nodes`（默认 200000）。超预算的边界标记 `[TRUNCATED]` 端点并在 `Notes` 说明（BFS 从目标开始，保证靠近目标、即 ECO 最关心的部分被完整保留）。

### 5.2 端点分类

| 端点 | 判定 |
|---|---|
| `[REG]` | lib 中带 `ff` group 的 cell，追到 Q（记 Q）或 QN（记为取反） |
| `[LATCH]` | lib 中带 `latch` group 的 cell |
| `[UNKNOWN]` | cell 既不在 lib 中也不在模块索引中（SRAM、硬核等）。报告列出实例名、cell 类型，以及该 net 相连的、方向未知的 pin。若某 net 没有已知驱动，只连到未知 cell 的 pin，也归为这一类 |
| `[PORT-IN]` | 顶层模块的输入端口（一次输入） |
| `[INOUT]` | inout / 三态 |
| `[CONST]` | `1'b0/1'b1`、tie cell（lib 中函数为常量）、`supply0/supply1` |
| `[UNDRIVEN]` | 无驱动 |
| `[MULTI-DRIVER]` | 多驱动（报告全部驱动源） |
| `[LOOP]` | 组合环，作为端点切断并在 `Notes` 报告环路成员 |

其他约定：

- `assign a = b;` 别名穿透；`assign a = ~b` 穿透并记取反；`assign` 里出现其他表达式时作为端点报告（不猜）。
- 未知 cell 的 pin 方向未知时的假设：若该 net 另有已知驱动，则把未知 pin 视为负载（输入），不报错；这属于假设，写进 `Notes`。
- 不穿过寄存器继续向前追多拍（不在本期范围）。

### 5.3 跨模块

- **向下**：驱动若是子模块实例的输出端口，进入该实例上下文递归追溯（`u_core/u_fsm/U12/...`）。
- **向上**：若碰到当前模块的输入端口，且当前实例不是顶层，则回到父上下文，继续追父模块中连到该端口 pin 的 net。
- 由于 `--inst` 给出父链，多例化歧义不存在。
- 向上/向下都计入同一节点预算，另有 `--max-hier-depth`（默认 8）限制层次深度；`--no-cross` 关闭跨模块（子模块输出记为 `[SUBMODULE-OUT]`，输入端口记为 `[PORT-IN]`）。
- 命名规则见 §3：目标实例内部的名字不带前缀，其他实例里的名字用从顶层开始的完整路径。

## 6. 化简与还原引擎

采用方案 B：**函数规范化 + 模式还原**，不依赖门级结构形状。

### 6.1 BDD 与变量排序

- 自实现小型 ROBDD（约几百行），支持 `and/or/xor/not/ite`、`restrict(cofactor)`、`sat_count`、`min_/max_`、节点计数。
- 每个端点是变量。变量顺序按启发式静态排序：
  1. 单比特信号（控制、使能、选择）在前。
  2. 总线按位宽升序；等宽总线按位索引降序**交错**排列（`a[3], b[3], a[2], b[2], ...`）。
  - 窄总线在前 → mux / 索引 / 桶形移位器为线性规模（选择位在前）。
  - 等宽交错 → 比较器、加减法为线性规模（这是为什么交错，而不是把 A 全部排在 B 前面）。
- 节点预算：单 net 超过约 100k 节点、或总计超过约 2M 节点 → 该 net 作为**切点**（新变量），下游只能给局部式，标记 `[CUT]`。乘法是典型爆炸源（见 §6.6）。
- 排序失败时的回退：按 DFS 扇入顺序重排一次；仍爆炸则切点。

### 6.2 每个 cell 的函数

lib 的 `function` 表达式（`& | ^ ! + * ' ()` 等）解析成表达式树，按 pin 组装。时序 cell 的 Q 端是端点，不展开。

### 6.3 还原流水线

对每个候选 wire（锥内的中间 wire + 目标）：

1. 取该 net bit 的 BDD（关于端点变量）。
2. 递归分解，直到叶子可被识别器命中：
   - **不相交支撑分解**：按总线分组，尝试 `f = g(X) & h(Y)`、`f = g(X) | h(Y)`、`f = g(X) ^ h(Y)`（用 `∃Y f` / `∃X f` 构造后验证）。
   - **mux 分解**：选一个单比特变量 `s`，`f = s ? g : h`（cofactor），优先选标量控制信号，选让两侧最简的那个变量。
   - 递归深度、候选个数都有上限，超限回退到布尔式。
3. **叶子识别器**（见 §6.4）：命中则产出字级/总线级表达式；否则产出最简与或式（Minato–Morreale ISOP）。
4. **自检**（见 §7）：把渲染出的表达式反算回 BDD 与原函数比对。
5. **局部式**：独立于 BDD，直接由驱动 cell 的函数代入输入 net 名生成（穿透 BUF/INV），如 `!(n1 & n2 | n3 & n4)`。这保证了即使 BDD 爆炸，也总有可读输出。

渲染语法：Verilog 风格 `! & | ^ ?: == != < <= > >= + - * >> << {} []`；表达式取位写作 `(a + b)[3]`（便于阅读，非严格 Verilog 语法，文档中说明）。

总线分组：按名字还原 `base[index]`；兼容 `\base[3] `、`base_3_`（DC `change_names` 风格）。连续索引渲染成 `base[hi:lo]`；不连续渲染成拼接 `{base[5], base[3:2]}`。

寄存器端点显示名：实例名含 `_reg` 时由实例名推导（`\cnt_reg[3]` → `cnt[3]`，`cnt_reg_3_` → `cnt[3]`），否则用 Q 端的 net 名。报告里同时给出实例名与 Q net 名。这样 `state[3:0] == 5` 这种可读形式自然出现。

### 6.4 识别器清单（对应你提的第 3 点）

统一做法：**假设—验证**。因为 BDD 是规范表示，验证是精确的（节点指针相等，不是启发式）。

| 模式 | 识别方法 | 可行性 | 限制 |
|---|---|---|---|
| `bus == k` / `!=`，`bus == bus` | 函数只依赖一根总线/两根总线，且为等值函数 | 高，精确 | 无实质限制 |
| `bus < k`、`<=`、`>`、`>=`（无符号） | 函数只依赖一根总线的某个连续位区间，且其 on-set 在整数域上是连续区间 `[lo, hi]`（`sat_count == hi-lo+1`，`min`/`max` 由 BDD 求得）。`lo==0` → `bus <= hi`；`hi==max` → `bus >= lo`；`lo==hi` → `==`。区间补集 → `bus < lo \| bus > hi` 或 `!(inside {...})` | 高，精确 | 位区间需连续 |
| 同一根总线上的多值条件 | on-set 是若干离散值 → `bus inside {5, 9}` | 高，精确 | 值的个数 ≤ 8，否则回退布尔式 |
| 有/无符号比较 `bus_a < bus_b` 等 | 支撑为两根总线，构造 `<`、`<=`、`==`、`!=` 的 BDD 直接比较（含补集即 `>`、`>=`）；先试无符号，再试 `$signed` | 高，精确 | 位宽可零扩展对齐；支持符号扩展变体 |
| `bitmap[idx]`（索引/查表） | 选择位枚举：候选选择总线 S（位宽 ≤ 10，最多 1024 个 cofactor），逐个取值求 cofactor，检验每个 cofactor 是否为常量或某个数据位的字面量，得到映射 `g: s -> data_bit`。`g(s) = s` → `bitmap[idx]`；`g(s) = s+k` 且越界为 0 → `(A >> S)[k]`；`g(s) = k-s` → `(A << S)[k]`；`g` 任意但每项简单 → `mux(S){...}` | 高，精确 | 选择位宽 ≤ 10；cofactor 需为字面量/常量（否则回退布尔式） |
| 变量移位 `>>`、`<<`、`>>>` | 同上一条：位 k 的移位就是索引映射，算术右移的越界补 MSB | 高，精确 | 选择位宽 ≤ 10 |
| 常量移位 `>> const`、`<< const` | 不产生任何逻辑：位 k 的 `a >> 3` 就是 `a[k+3]` 本身。追溯时直接表现为别名/取反（已由局部式与 aliases 覆盖），不需要额外识别器 | 天然支持（形式是 `a[5]` 而非 `(a >> 3)[0]`） | 只有总线级分组输出才能显示成 `y = a >> 3`，单比特追溯上无意义 |
| `+`、`-`（位 k） | 支撑 ⊆ `A[k:0] ∪ B[k:0]`；构造 `A+B` 第 k 位的 BDD 与之比较。常量操作数可**反解**：由 BDD 求 `f(0)` 和使 `f` 变化的最小 `A_low`，得到 `K mod 2^(k+1)`，再验证 | 中高，精确 | 操作数需**对齐**（各操作数切片的 LSB 为位 0，或为符号扩展形式）。非对齐（如 `a[7:4] + b[3:0]`）回退布尔式。支持 `A+B`、`A+K`、`A+B+cin`；三个以上操作数回退 |
| 进位 net | 进位就是"低位和的最高位"：`(A[m:0] + B[m:0])[m+1]`，同一个识别器即可命中 | 中高，精确 | 同上。前缀加法器内部的 propagate/generate 中间网不是和的某一位，回退布尔式 |
| `*`（位 k） | 小位宽：构造 `A*B` 第 k 位的 BDD 精确验证（默认乘积位宽 ≤ 8×8，受节点预算约束）。宽位宽：BDD 对乘法是**指数级**（任意变量序，Bryant 1991），此时用**位并行仿真**在若干随机向量上匹配，命中则标记 `[simulation-matched, unproven]`。常量乘法 `A*K` 通常可行 | 低-高，取决于位宽 | 宽乘法只能给"未证明"结论，报告里显式标注，不冒充精确 |
| 任意未命中 | 最简与或式（ISOP），如 `a & !b & c` | 高 | 无 |

字级识别的边界：

- 追溯的是**单根 wire**，所以字级算符以"某一位"的形式出现，如 `(cnt[3:0] + 1)[3]`。
- 操作数必须是**端点总线**（寄存器/端口总线）或常量。操作数本身是中间逻辑时（如 `(a & mask) + b`），中间网通常是 `n123` 这类无总线结构的名字，无法组成操作数，回退布尔式。
- 字级算符外面包着的使能、复位、选择逻辑由 §6.3 的分解剥离，例如 `rst ? 1'b0 : (en ? (cnt[3:0] + 1)[3] : cnt[3])`。
- 所有回退都是回到正确的布尔式，只是可读性变差，不会出错。

### 6.5 输出预算

- 端点式超过预算（默认 64 个原子项，或依赖端点数 > 24）时省略端点式，改打印依赖端点数与 `--expand` 提示。
- 局部式始终输出（它对大小天然不敏感）。

### 6.6 未证明结果的处理

`*` 宽位宽等 BDD 不可行的情形，允许输出仿真匹配的表达式，但必须：

- 行尾用 `[simulation-matched, unproven]` 明确标注；
- 默认匹配 4096 个随机向量 + 边界向量（全 0、全 1、单比特走 1、进位/借位边界）；
- `--strict` 时禁止输出未证明结果，只给布尔式。

### 6.7 不做的事（本期）

- 穿过寄存器向前追多拍
- 把多根 wire 合并成总线级输出（如 `{n13,n12,n11,n10} = cnt[3:0] + 1`、`y = a >> 3`）
- case / if 伪 RTL 视图
- 磁盘索引缓存
- 时序例外、clock gating 单元的内部结构展开
- 形式化等价检查（SAT）作为乘法证明手段

## 7. 正确性保障

ECO 场景下错误的表达式比没有表达式更危险，因此每次运行都做**内建自检**：

- 每条渲染出的表达式都反算回 BDD，与原始函数比对（同 manager、同变量序，比较根节点）。
- 仿真匹配的结论走独立路径（位并行仿真：对门级锥逐向量求值，并与表达式的求值结果比对）。
- 自检失败时：该行退回未化简的布尔式，并在 `Notes` 里给出 `INTERNAL: lifted expression mismatch for <net>`。绝不输出已知不一致的表达式。

## 8. 错误处理

- 文件打不开、lib 解析失败：报行号/字节偏移，非零退出。
- 网表语法错误：报行号与上下文，跳过该语句并警告（尽量继续）。
- 例化路径找不到：列出候选（编辑距离最近的若干条）。
- wire 找不到：列出同基名的可用位（`next_state[3:0]` 存在、`next_state[7]` 不存在时给出提示）。
- 报告内所有不确定性都进 `Notes`，不静默丢弃。

## 9. 测试策略

- **TDD**：先写测试再写实现。
- `grammar.example` 两条逐字还原（`cnt[3:0] == 5`、`sel ? a : b`）。
- 夹具：手写小 `.lib` + 小网表，覆盖各类端点（REG/LATCH/UNKNOWN/CONST/UNDRIVEN/MULTI-DRIVER/LOOP/INOUT/TRUNCATED）、命名风格（`\cnt_reg[3] `、`cnt_reg_3_`、展平层次名）、跨模块上下、`--no-cross`、`--filter`。
- 随机等价性测试：随机生成小锥，检查还原结果在随机向量上与门级求值一致。
- 大网表：`src/bin/gen_netlist.rs` 生成约一千万行、含 FSM、数据通路、SRAM 黑盒、多例化模块、转义标识符的层次化网表；测索引时间、查询时间、峰值内存，数字写进 README。

## 10. 代码结构

```
src/
  main.rs            CLI（clap）
  liberty/           Liberty 子集解析：lexer / parser / function 表达式 / CellLib
  netlist/           lexer / index（模块范围、被例化类型）/ parser（按需解析）/ design（惰性模块存储、实例路径解析）
  trace/             锥遍历（实例上下文）、端点分类、预算控制
  logic/             bdd / expr（AST 与求值）/ lift（分解 + 识别器）/ bus（名字→总线分组）/ sim（位并行仿真）
  report/            报告渲染
tests/               集成测试 + fixtures/
src/bin/gen_netlist.rs  合成大网表生成器
docs/superpowers/specs/  设计文档
```

依赖（尽量少）：`clap`、`memmap2`、`rustc-hash`、`memchr`、`anyhow`、`rayon`（仅用于退化路径的并行全解析）。
